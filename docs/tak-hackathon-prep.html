01 The 60-second orientation

TAK = Team Awareness Kit. A geospatial situational-awareness platform: shared map, live position tracking, chat, markers, routes, and sensor feeds across a team. Originally US gov, now with a large open-source ecosystem. Everything is glued together by one message format (CoT) flowing through a central server.

Clients

ATAK / iTAK / WinTAK

Android, iOS and Windows clients. ATAK-CIV is the free civilian build (register on tak.gov). Plugins extend ATAK — that's the usual hackathon target.

Backbone

TAK Server

Routes CoT between all clients, handles auth (X.509 certs), data packages, video, and federation. The IP they give you is almost certainly this.

Web / Cloud

CloudTAK / WebTAK

Browser-based client + API (CloudTAK is MIT-licensed, arguably the biggest open-source piece). Great for a no-install demo surface.

Mental model: sensors & clients emit CoT events → TAK Server fans them out → every connected map redraws. If your hack can produce a valid CoT stream to their server, it shows up on everyone's screen. That's the whole game.

03 Cursor-on-Target (CoT) — the one thing to actually learn

Every position, marker, chat, and sensor report is a CoT <event>. Learn this XML and you can talk to the whole system. Detail child elements are free-form, so you can carry custom payloads.

<!-- A friendly ground unit at a location -->
<event version="2.0"
       uid="hack-team-alpha-01"          <!-- stable unique id per entity -->
       type="a-f-G-U-C"                <!-- affiliation-domain-... (see table) -->
       how="m-g"                       <!-- how derived: m-g = machine/GPS -->
       time="2026-08-15T02:10:00Z"
       start="2026-08-15T02:10:00Z"
       stale="2026-08-15T02:15:00Z">       <!-- drops off map after this -->
  <point lat="-27.4705" lon="153.0260"
         hae="25.0" ce="5.0" le="10.0"/>  <!-- WGS84; hae/ce/le in metres -->
  <detail>
    <contact callsign="ALPHA-01"/>
    <__group name="Cyan" role="Team Lead"/>
    <remarks>your custom payload goes here</remarks>
  </detail>
</event>
Event attributes (all required except noted)
  • uid — persistent id for the entity; reuse it to move a marker
  • type — hierarchical type string (table below)
  • how — data origin, e.g. m-g machine-GPS, h-e human-entered
  • time / start / stale — ISO-8601 UTC; stale is when it disappears
  • point — lat,lon,hae (height above ellipsoid), ce/le error
  • detail — no fixed schema; put anything here
Common CoT type codes
a-f-G-U-CFriendly ground combat unit
a-h-GHostile ground
a-u-GUnknown ground
a-f-AFriendly air track
b-m-p-s-p-locMission waypoint / marker
b-t-fGeoChat message

Affiliation: friendly · hostile · neutral · unknown. Domain: Ground · Air · Sea.

04 Streaming to their server IP

This is the part they described — "an IP to stream out on." Two protocol generations and three framings. Know the ports and you're connected in minutes.

PathPortNotes
Streaming TCP (plain)8087Simplest. Newline/null-delimited CoT XML.
Streaming TLS (cert auth)8089Production path. Needs client cert from data package.
Mesh SA multicast (no server)239.2.3.1:6969Local UDP mesh; devices on same LAN see each other.
Cert enrollment / web API8443 / 8446Where clients pull certs & data packages.
TAK Protocol v0 vs v1. v0 = plain XML CoT. v1 = the same data as Protobuf, framed with a magic byte 0xBF (191). Stream framing: 191 <varint length> <payload>. Mesh framing: 191 1 191 <payload>. Libraries like takproto handle all three so you rarely hand-roll this.

Fastest possible "put a marker on everyone's map" — Python + pytak:

# pip install pytak
import asyncio, pytak
import xml.etree.ElementTree as ET
from configparser import ConfigParser

class Sender(pytak.QueueWorker):
    async def run(self):
        while True:
            evt = ET.Element("event")
            evt.set("version","2.0"); evt.set("type","a-f-G-U-C")
            evt.set("uid","hack-alpha-01"); evt.set("how","m-g")
            evt.set("time",pytak.cot_time()); evt.set("start",pytak.cot_time())
            evt.set("stale",pytak.cot_time(120))
            pt = ET.SubElement(evt,"point")
            pt.set("lat","-27.4705"); pt.set("lon","153.0260")
            pt.set("hae","25"); pt.set("ce","5"); pt.set("le","10")
            await self.put_queue(ET.tostring(evt))
            await asyncio.sleep(5)

async def main():
    cfg = ConfigParser()
    cfg["x"] = {"COT_URL": "tcp://THEIR_SERVER_IP:8087"}   # TLS: tls://IP:8089 + cert paths
    tool = pytak.CLITool(cfg["x"]); await tool.setup()
    tool.add_tasks({Sender(tool.tx_queue, cfg["x"])})
    await tool.run()

asyncio.run(main())
For TLS (8089) add PYTAK_TLS_CLIENT_CERT / PYTAK_TLS_CLIENT_KEY pointing at the cert & key you extract from the server's data package (.p12 → convert with openssl). If they hand you a data package, that's where your creds live.

05 Pick your build path

Match the path to your team's stack and the (unknown) problem statement. You can decide fast once you see it — but pre-install the one you're most likely to use.

Fastest to demo

Python / bridge

pytak or takproto to push external data (sensors, APIs, ML output) into TAK as CoT. Ideal for "get X onto the map." No Android build. Runs anywhere.

Deepest integration

ATAK plugin

Java/Kotlin on the SDK (5.5/5.6 line). New UI, tools, overlays inside ATAK itself. Highest wow-factor, steepest setup — Android Studio + keystore + dev APK.

No-install surface

Web / CloudTAK

Browser client + REST/WebSocket API. Great for dashboards, judges' view, or a control panel that doesn't need a phone in hand.

ATAK plugin setup (if you go that route): Android Studio (Narwhal+), Gradle 8.13 / AGP 8.9, build variant civDebug, set run config Launch → "Nothing" (plugin loads on top of the base app), install the dev ATAK APK from the SDK, then build & deploy. SDK 5.5+ removed the old Java-version headaches and added Jetpack Compose support. Kotlin + MapComponent (entry point) + DropDownReceiver (UI) is the standard skeleton.

06 Idea seeds (adapt to the problem statement)

Patterns that judge well at TAK hackathons — most reduce to "fuse a new data source onto the shared map" or "make a decision faster in the field."

EASY

Live sensor → map bridge

Pull a public feed (weather, ADS-B, AIS, traffic, fire/flood alerts) and stream it as CoT markers. Instant visible payoff.

MED

AI object detection → CoT

Run a vision model on a drone/camera feed, emit detections as hostile/unknown markers with confidence in the detail block.

MED

GeoChat bot / assistant

An agent that answers over GeoChat: nearest asset, ETA, "summarise activity in this area." Ties in nicely with an LLM.

AMBITIOUS

In-ATAK plugin tool

New drop-down: route optimiser, medevac coordinator, comms-relay planner, or offline mesh status — rendered right on the operator's map.

EASY

Web ops dashboard

CloudTAK/WebSocket dashboard aggregating all CoT into charts + a judges'-eye overview. Good "second screen" for the demo.

MED

Data-package generator

Tool that builds shareable overlays/geofences (KML/GeoJSON → data package) from an address, mission brief, or CSV.

07 Pre-event checklist

Knock these out before you walk in so the weekend is all building.

  • Register a tak.gov account — required for ATAK-CIV APK + Plugin SDK (approval can lag, do it first)
  • Install ATAK-CIV on an Android phone/tablet, or an emulator, and click around
  • Stand up a throwaway server — FreeTAKServer or taky locally so you can test CoT before the event server exists
  • Pre-install a build path — pip install pytak takproto and/or Android Studio + Plugin SDK unzipped
  • Grab CoT libraries for your language — pytak (Py), node-CoT (JS), cotlib (Go)
  • Test the loopback — run the pytak sender above against your local server and watch a marker appear
  • Learn the cert flow — how to pull a data package & extract .p12 → cert/key for TLS:8089
  • Bring the kit — Android device + USB cable, laptop w/ Android Studio, phone charger, hotspot as backup LAN
